# Velin Web SSH 产品需求文档

> 文档状态：需求完善稿 v0.2  
> 产品名称：Velin Web SSH  
> 产品形态：自托管 Web 应用  
> 前端技术栈：Vue 3 + TypeScript + Vite + Element Plus + xterm.js  
> 后端技术栈：Go + SQLite  
> 适配终端：桌面浏览器、平板、手机浏览器

## 1. 项目概述

开发一套名为 Velin Web SSH、需要登录后使用的 Web SSH 工具。产品交互和视觉体验参考 Termius，核心能力包括主机管理、SSH 会话管理、多会话并行、多窗口布局、终端外观设置和跨浏览器生命周期的会话恢复。

最关键的能力是“会话记忆”：每个 Velin Web SSH 终端由远程主机上的专属 `tmux` 会话托管。用户刷新页面、关闭浏览器标签页、关闭浏览器，甚至 Go 服务重启后，只要远程主机和该 `tmux` 会话仍存活，任务就继续运行；用户重新登录后可以恢复此前的工作区、终端标签、窗口布局和终端输出，并重新附着原会话。用户主动关闭 Velin 的终端标签时则视为明确终止该会话。

## 2. 产品目标

1. 用户可以在浏览器中安全、稳定地管理主机并使用 SSH。
2. 支持多个 SSH 会话并行运行，且可以在同一页面内分屏操作。
3. 页面刷新或浏览器离线不影响服务端正在运行的 SSH 会话。
4. 用户重新进入系统后，可以尽可能恢复离开前的操作现场。
5. 桌面端提供高效率操作体验，移动端保证主要功能可用且易操作。
6. 首期采用单体 Go 服务与 SQLite，保持部署简单，并为后续扩展预留边界。

## 3. 名词定义

| 名词 | 定义 |
| --- | --- |
| 主机 | 一个可连接的 SSH 目标配置，包括地址、端口、用户名和认证方式等 |
| SSH 连接 | 后端与远程主机建立的底层网络连接 |
| 终端会话 | 基于 SSH 连接创建的交互式 Shell/PTY |
| 工作区 | 用户当前打开的标签、分屏布局及活动会话集合 |
| 会话记忆 | 保存工作区状态，并通过 Velin Web SSH 专属 tmux 命名空间重新附着远程持久会话 |
| 输出回放 | 客户端离线期间，通过后端内存缓冲或远程 tmux history 保留有限终端输出，重连后发送给客户端 |

## 4. 用户与权限

### 4.1 用户角色

首期至少支持以下角色：

- 管理员：管理用户、全局安全设置、系统状态和自己的主机/会话。
- 普通用户：管理自己的主机、凭据、会话及个人设置。

### 4.2 数据隔离

- 每个用户只能查看和操作自己的主机、凭据、工作区及会话。
- 管理员默认不能直接读取用户保存的明文密码或私钥。
- 所有 WebSocket 会话和 HTTP API 都必须校验登录身份及资源归属。
- 不允许通过修改会话 ID、主机 ID 等方式访问其他用户资源。
- 用户被禁用后禁止新登录和新建连接；其已有远程 tmux 任务默认不被静默终止，由管理员按策略处理。
- 管理员执行终止他人会话、删除凭据、导出数据等高风险操作时必须记录审计事件。

### 4.3 账户安全

- 支持查看当前登录设备、登录时间、来源 IP 和最后活动时间。
- 支持撤销单个登录设备或退出全部设备。
- 管理员可配置密码强度、登录有效期、失败锁定阈值和首次登录强制改密。
- P1 支持基于 TOTP 的双因素认证和恢复码。
- P2 可扩展 OIDC/OAuth 2.0、LDAP 等统一身份认证。

## 5. 功能需求

### 5.1 登录与账户

- 打开系统时，未登录用户只能访问登录页。
- 支持用户名和密码登录。
- 支持安全退出，退出后撤销当前登录令牌。
- 支持“保持登录”选项及可配置的登录有效期。
- 支持修改个人密码。
- 管理员可创建、禁用、重置和删除用户。
- 连续登录失败达到阈值后触发临时锁定或限流。
- 登录过期时只断开浏览器访问，不终止远程 tmux 会话；重新认证后允许恢复。
- 登录成功后直接进入最后使用的工作区；首次使用时进入空工作区并打开主机侧栏。
- 支持找回登录状态，但自托管首期不内置邮件找回密码，由管理员执行重置。

### 5.2 主机管理

- 新增、编辑、复制、删除主机。
- 主机字段至少包括：
  - 名称
  - 分组
  - 标签
  - 主机地址或域名
  - SSH 端口，默认 22
  - 用户名
  - 认证方式
  - 启动目录（可选）
  - 连接超时（可选）
  - Keepalive 间隔（可选）
  - 备注
- 支持按名称、地址、分组和标签搜索或筛选。
- 支持收藏常用主机和最近连接列表。
- 支持连接前测试主机网络与认证是否可用。
- 删除主机时，需要提示其关联的活动会话；不得静默终止正在运行的任务。
- 支持快速连接：输入 `user@host:port` 后临时连接，并可在连接成功后另存为主机。
- 支持批量移动分组、添加标签、收藏和删除；批量删除仍需检查活动会话。
- 支持主机列表与紧凑表格两种视图，并展示最近连接状态和延迟。
- P1 支持从 OpenSSH `config` 导入主机，识别 `HostName`、`User`、`Port`、`IdentityFile` 和 `ProxyJump`；未知字段保留警告而不是静默丢弃。
- P1 支持导出脱敏主机配置，默认不包含密码、私钥和密钥口令。

### 5.3 SSH 认证与凭据

- 支持密码认证。
- 支持 SSH 私钥认证，并支持有密码保护的私钥。
- 支持为连接临时输入凭据且不保存。
- 支持保存凭据并复用于一个或多个主机。
- 保存的密码、私钥和私钥口令必须加密后写入 SQLite，不得明文存储或写入日志。
- 主机首次连接时显示服务端主机指纹，用户确认后保存。
- 后续主机指纹变化必须阻止自动连接并明确警告，用户确认后才可更新。
- 支持一个主机切换不同用户名或凭据，但恢复 tmux 会话时必须使用创建它的同一远程账号。
- 私钥导入时检测格式和加密状态；不支持的格式给出具体错误，不把原文写入日志。
- 凭据删除前列出引用它的主机和可恢复会话；不得导致用户误以为远程 tmux 任务已被终止。
- P1 支持键盘交互式认证及 SSH Agent 转发，并默认关闭 Agent 转发。
- P1 支持跳板机链路，每一跳分别校验主机指纹，不允许自动信任未知跳板机。

### 5.4 SSH 高级连接

- 支持配置连接超时、ServerAlive 间隔、最大重试次数和初始工作目录。
- 支持选择终端类型，默认 `xterm-256color`，并允许管理员限制可选值。
- 支持远程环境变量白名单；禁止把任意服务端环境变量自动注入远程主机。
- 支持 UTF-8，终端编码异常时给出提示；P0 不承诺任意传统字符集转换。
- 支持发送 SSH keepalive，并区分浏览器 WebSocket 心跳与远程 SSH keepalive 状态。
- P1 支持单级和多级跳板机、HTTP/SOCKS 代理。
- P1 支持本地、远程及动态端口转发，展示监听地址、端口、流量和状态；删除转发需精确关闭对应通道。
- 端口转发默认仅绑定服务端环回地址，监听公网地址需要管理员显式授权。

### 5.5 终端基本能力

- 使用 WebSocket 在浏览器与 Go 后端之间传输终端输入、输出和控制消息。
- Go 后端通过 SSH 建立交互式 PTY，并将终端尺寸同步到远程端。
- 支持常规 Shell 输入、ANSI 色彩、光标、退格、组合键和全屏程序。
- 支持复制、粘贴、全选、清屏和终端内搜索。
- 支持鼠标选择文本及链接识别。
- 支持浏览器窗口或分屏区域变化时自动调整行列数。
- 支持手动重连、关闭会话和强制终止会话。
- 展示清晰的连接状态：连接中、已连接、重连中、已离线、已断开、认证失败、主机不可达。
- 网络短暂中断时自动重连 WebSocket，并重新挂接原终端会话。
- 支持下载当前可见终端文本，导出前明确提示其中可能包含敏感信息。
- 支持响铃的视觉提示，浏览器声音提示默认关闭。
- 支持粘贴保护：多行或包含控制字符的内容粘贴前提示确认，并允许用户配置。
- 支持右键上下文菜单，但不阻断浏览器和系统必要的复制粘贴能力。
- 支持终端标题由远端 OSC 标题更新；页面展示时需要转义，禁止注入 HTML。

### 5.6 会话管理

- 从主机列表快速创建会话。
- 同一主机允许打开多个独立会话。
- 会话列表展示会话名称、主机、连接状态、创建时间和最近活动时间。
- 支持会话重命名、复制新开、断开和终止。
- 支持“移到后台”：从当前工作区隐藏终端标签，但远程 tmux 会话继续运行，可从后台会话列表恢复。
- 用户主动点击终端标签的关闭按钮时，视为终止会话，而不是仅隐藏视图。
- 关闭终端标签前显示确认，明确说明会精确结束对应远程 tmux session，其中运行的进程也会终止；确认后执行 `kill-session`。
- 关闭确认框同时提供“移到后台”入口，用户需要保留任务时可以改用该动作。
- 同一会话被多个浏览器观看时，确认关闭属于全局终止：tmux session 结束，所有客户端收到结束事件并同步关闭或标记该终端标签。
- 只读观察端默认不能直接关闭并终止会话，需要先取得控制权；管理员按权限执行终止时除外。
- 已确认远程 tmux session 不存在的结束标签可以直接从工作区移除，不再执行远程终止命令。
- 对活动会话执行关闭标签、终止会话或批量终止时必须二次确认。
- 支持按用户配置会话最大数量、空闲保留时间及最长生命周期。
- 会话支持置顶、按主机或状态筛选，并区分“当前已附着”“后台运行”“等待认证”“远程已结束”。
- 支持批量恢复后台会话，但需要控制并发数，避免同时连接大量主机。
- 用户退出 Velin Web SSH 时可选择仅退出账号或同时终止自己的全部远程会话；默认仅退出账号。
- 管理员终止用户会话前必须显示主机、远程账号、创建时间和最后活动时间，并二次确认。
- 默认不因移到后台、退出账号、关闭浏览器标签页、关闭浏览器或 Go 服务维护自动终止 tmux 会话；主动关闭 Velin 终端标签除外。
- 若管理员启用自动清理，必须明确展示会终止远程任务；清理前再次校验所有权标记，并在审计日志中记录策略和目标。

### 5.7 多标签与多窗口共存

- 顶部或主工作区提供终端标签栏。
- 支持多个会话标签快速切换。
- 单个工作区支持水平分屏和垂直分屏。
- 每个分屏单元可以显示不同会话，也可以打开同一主机的新会话。
- 支持拖动调整各分屏大小。
- 支持关闭分屏、最大化当前分屏和恢复布局。
- 支持键盘快捷键切换标签和焦点。
- 保存标签顺序、当前活动标签、分屏树结构、分屏比例和焦点位置。
- 浏览器原生多个标签页可同时连接同一账户。
- 同一终端会话默认采用“单写多读”：一个客户端持有输入权，其他客户端只读观看，避免并发键盘输入相互干扰。
- 只读客户端可请求接管；原控制端在线时显示确认，原控制端离线或超时后由服务端自动转移控制权。
- 只有持有输入权且当前可见的客户端负责 PTY 尺寸；只读客户端缩放不得改变远端行列数。
- 界面持续显示当前控制设备，并提供主动释放控制权功能。
- P1 可提供显式“协作输入”模式，启用时必须向所有观察者显示状态。

### 5.8 会话记忆与持续运行（核心）

#### 5.8.1 必须实现的体验

- 刷新页面后，恢复刷新前打开的标签、分屏、活动焦点和终端会话。
- 关闭浏览器再打开并登录后，恢复上次工作区。
- 浏览器关闭期间，远程命令由 Velin Web SSH 创建的 `tmux` 会话托管并继续运行；是否存在浏览器或 Go WebSocket 不影响任务生命周期。
- 重新进入时，先恢复布局，再重新挂接仍存活的会话。
- 重连后回放离线期间保留的终端输出，并继续实时接收新输出。
- 如果 SSH 连接已断开但远程 `tmux` 会话仍存在，后端自动重新建立 SSH 并附着原会话。
- 如果远程 `tmux` 会话已经结束，仍恢复对应终端标签并展示结束时间、退出原因和可用的历史输出，同时允许一键新建会话。
- 对恢复失败的单个会话进行独立提示，不影响其他会话恢复。

#### 5.8.2 服务端会话要求

- 终端任务必须归属于远程 `tmux` 会话，不能依赖某一个 WebSocket、浏览器页面或 Go 进程存活。
- WebSocket 断开时只解除客户端订阅，不关闭 SSH/PTY，也不结束远程 `tmux` 会话。
- 每个终端会话使用不可猜测的唯一 ID，并绑定用户 ID。
- 后端记录会话状态、主机、创建时间、最后活动时间、客户端连接数和终止原因。
- 后端为每个活动会话维护有上限的输出环形缓冲区，避免无限占用内存。
- 客户端使用输出序号或游标续传，减少重连时的重复或遗漏。
- 缓冲区已覆盖的旧输出无法完整回放时，必须向用户显示“部分历史输出已省略”。
- 同一终端会话在任一时刻最多建立一个后端 tmux 附着通道；多个浏览器客户端由 Go 服务统一广播，不能各自直接 attach 造成尺寸和输入竞争。
- 服务端维护输入控制租约，校验每条输入及 resize 消息是否来自当前控制端。
- 服务端支持配置：
  - 无客户端连接时的保留策略，默认永久保留直到显式终止
  - 会话最大空闲时长，默认不限制
  - 会话最大生命周期，默认不限制
  - 单会话输出缓冲上限
  - 单用户最大活动会话数

#### 5.8.3 tmux 托管与隔离规则

- `tmux` 托管属于 P0 核心能力，目标主机必须安装兼容版本的 `tmux`；连接时先执行能力探测。
- 使用独立 socket 命名空间：`tmux -L velin-webssh-<deployment_id>`。`deployment_id` 由本套 Velin Web SSH 安装生成并持久保存，必须仅包含安全字符，且不能由浏览器任意传入。
- 每个终端使用 `ws_<session_uuid>` 作为 tmux session 名。名称由后端生成，不使用主机名、用户名等可能冲突或需要 shell 拼接的输入。
- 创建时写入 Velin 所有权标记和会话 UUID；恢复或删除前同时校验 socket、session 名和所有权标记，标记不符时停止操作并记录安全事件。
- 创建时设置合理的 tmux `history-limit`，具体默认值由容量测试确定，并允许管理员设置全局上限。
- 创建、检测、附着、捕获历史和终止时必须同时指定专属 socket 与精确 session 名。
- Velin Web SSH 不读取、不附着、不重命名、不清理远程用户默认 socket 或其他自定义 socket 中的 tmux 会话。
- Velin Web SSH 不执行无目标的 `tmux kill-server`；终止时只能执行专属 socket 下精确的 `kill-session -t <session_name>`。
- “移到后台”、关闭浏览器标签页或网络断开只执行 detach 语义，远程任务继续。
- 用户确认关闭 Velin 终端标签、明确选择“终止会话”或命中已启用的清理策略时，才结束对应 tmux session。
- SQLite 保存主机 ID、Velin Web SSH 会话 ID、`deployment_id`、tmux socket 名、tmux session 名及状态，用于后端重启后重新发现和附着。
- tmux socket 属于发起 SSH 登录的远程系统账号；恢复时必须使用同一远程账号，禁止跨账号寻找或操作 socket。
- 如果多个 Velin 用户共用同一个远程系统账号，远程 Unix 权限无法隔离这些 tmux 会话；应用层仍必须按所有者校验，但高安全场景应要求每人使用独立远程账号。
- tmux 命令参数必须由后端构造并严格校验/转义，禁止拼接来自客户端的原始 shell 文本。
- 目标主机未安装或无法运行 `tmux` 时，阻止创建“可记忆会话”，给出明确检测结果和安装提示；可提供显式的临时直连模式，但必须标记为不可恢复。

#### 5.8.4 恢复能力与边界

- 页面刷新、浏览器关闭、客户端断网：重新订阅或重建 SSH 后附着原 tmux session，任务继续运行。
- Go 进程正常重启、崩溃或 Velin Web SSH 所在服务器重启：从 SQLite 读取映射，重新 SSH 登录目标主机并附着原 tmux session。
- 使用已保存的加密凭据时可以自动重新连接；使用临时凭据时，tmux 中的任务仍继续，但 Go 服务重启后必须由用户重新输入凭据才能附着。
- Go 服务离线期间产生的终端输出，通过 tmux history 获取有限回放；超过远程 `history-limit` 的内容无法恢复，界面必须明确提示可能存在历史截断。
- 重新附着时前端先重置终端缓冲，后端发送当前 pane 可恢复的历史和屏幕状态，再切换到实时字节流，避免重复输出或 ANSI 状态错乱。
- 正在运行 `vim`、`top` 等 alternate-screen 程序时，以 tmux 当前 pane 画面为恢复基准；不承诺恢复已经滚出 tmux history 的内容。
- tmux session 存在但 pane 中 Shell 已退出时视为远程已结束，不自动创建新 Shell 覆盖现场。
- 远程主机重启、tmux 进程被系统或用户终止、远程账号失效时，原会话无法继续；界面展示准确原因并允许新建会话。
- Velin Web SSH 不能保证被远程用户使用同一专属 socket 主动删除的会话继续存在。
- 如需跨远程主机重启继续执行任务，应使用 systemd、任务队列等更高层的远程任务托管机制，不属于 Velin Web SSH 终端会话记忆范围。

#### 5.8.5 工作区持久化

- 工作区结构保存到 SQLite，并在布局变化后及时更新。
- 客户端可用本地存储保存少量显示偏好和待同步状态，但 SQLite 是跨设备恢复的权威数据源。
- 至少保存：打开的会话引用、标签顺序、分屏结构、分屏比例、活动标签及最后更新时间。
- 同一账户从另一设备登录时，能够读取最近工作区；并发修改采用版本号或最后写入策略，避免静默覆盖。

### 5.9 终端样式与显示

- 提供浅色和深色主题，默认使用接近 Termius 的克制深色界面。
- 支持选择终端字体，并提供等宽字体回退。
- 支持调节字号、行高、字重、字间距、光标形状和光标闪烁。
- 支持配置前景色、背景色、光标色及 ANSI 色板。
- 支持终端透明度配置时，必须保证文字对比度和可读性。
- 支持缩放终端显示，布局变化后正确计算 PTY 行列数。
- 用户样式设置保存到服务端，登录其他设备后可同步。
- 支持恢复默认样式。

### 5.10 桌面端界面

- 登录后直接进入可工作的终端主界面，不设置营销型首页。
- 推荐布局：
  - 左侧边栏：主机、会话、历史及设置入口。
  - 顶部区域：终端标签、连接状态及工作区操作。
  - 中央区域：单终端或可调整的多分屏终端。
  - 抽屉/对话框：新增主机、连接认证和终端设置。
- 侧栏支持折叠，为终端释放空间。
- 常用动作使用图标按钮并提供悬浮提示。
- 终端区域优先占据可用空间，不使用多层卡片包裹。

### 5.11 移动端适配

- 支持常见手机和平板宽度，避免横向页面溢出。
- 侧边栏在移动端变为抽屉。
- 标签栏支持横向滚动和会话列表切换。
- 移动端默认一次聚焦一个终端；保留分屏配置，但可降级为分屏间切换，以保证可操作面积。
- 提供适合触控的快捷键工具栏，至少包含 Esc、Tab、Ctrl、Alt、方向键和常用组合键入口。
- 支持长按选择、复制、粘贴，并正确调用软键盘。
- 手机横竖屏切换后重新计算终端大小并同步 PTY。
- 所有关键点击区域符合触控尺寸要求，弹窗内容不超出视口。

### 5.12 历史与审计

- 记录连接历史：用户、主机、开始时间、结束时间、结果、来源 IP 和终止原因。
- 用户可查看自己的历史连接并快速重新连接。
- 管理员可查看系统级登录和连接审计事件。
- 默认不记录用户输入的命令明文，避免密码和敏感数据进入审计日志。
- 如未来增加完整终端录制，必须作为显式管理员策略，并向用户清楚提示，同时配置留存周期和访问权限。

### 5.13 设置与运维

- 个人设置：主题、语言、终端样式、快捷键、默认 Shell 行列偏好。
- 系统设置：会话配额、保留时长、登录策略、代理配置、审计留存。
- 提供服务健康检查接口。
- 展示 Go 服务版本、运行时间、活动用户数、活动 SSH 会话数和 WebSocket 连接数。
- 支持优雅关闭：停止接受新连接，尽量记录会话状态并给客户端发出通知。
- 管理员可查看会话配额、数据库大小、审计存储量及最近备份状态。
- 配置项变更需要校验范围，影响现有会话的变更需明确说明何时生效。

### 5.14 命令片段与快捷操作

- P1 支持创建个人命令片段，字段包括名称、分组、标签、命令正文和说明。
- 支持在当前终端插入命令但不自动执行，默认采用此模式。
- “发送并执行”必须是独立动作，包含换行、多命令或高风险模式时再次确认。
- 支持 `${variable}` 变量占位符，执行前弹窗填写；变量值只用于本次发送，不默认保存。
- 支持对多个已选会话批量发送命令，但默认关闭，并持续显示目标数量和主机清单。
- 不把命令片段变量、终端输入或执行结果写入普通应用日志。
- P2 可扩展团队共享片段、审批和只读模板。

### 5.15 SFTP 文件管理

- P1 支持基于当前主机凭据打开 SFTP 文件面板，并与终端并排使用。
- 支持目录浏览、面包屑导航、刷新、排序和隐藏文件显示切换。
- 支持上传、下载、新建目录、重命名、移动和删除。
- 上传下载展示进度、速度、剩余时间、失败原因，并支持取消与有限重试。
- 大文件采用流式传输，不把完整文件载入 Go 进程或浏览器内存。
- 文件覆盖、递归删除、移动到已有路径时必须确认；不得跟随未经确认的危险符号链接目标。
- 下载响应使用安全文件名和内容类型，预览远程文本时限制大小并进行内容转义。
- 服务端设置单文件大小、并发任务数和临时空间上限；传输临时文件需可清理。
- P2 支持断点续传、文件预览、权限修改和拖拽上传。

### 5.16 端口转发

- P1 支持本地转发、远程转发和动态 SOCKS 转发。
- 转发条目包含名称、关联主机、类型、源监听地址/端口、目标地址/端口和状态。
- 默认只允许绑定 Velin Web SSH 服务所在机器的环回地址；绑定局域网或公网地址需管理员授权并明确风险。
- 后端校验端口范围、地址策略和资源归属，禁止普通用户绕过主机访问策略。
- 转发断开后可按策略重连，界面显示失败原因和下一次重试时间。
- 终止单个转发只关闭对应 listener/channel，不影响同一 SSH 主机的终端和其他转发。
- 记录转发创建、启动、停止和失败事件，但默认不记录转发内容。

### 5.17 通知与任务关注

- P1 支持用户为终端会话开启“任务关注”。
- 支持在会话输出静默一段时间、出现终端响铃或匹配用户配置的非敏感文本时触发站内通知。
- 浏览器通知必须由用户主动授权，系统不得反复请求权限。
- 通知内容默认只显示主机别名和会话名称，不包含终端输出正文。
- 点击通知后定位到对应工作区和终端；会话需要重新认证时进入等待认证状态。
- P2 可扩展 Webhook 通知，但必须提供地址白名单、签名和敏感信息过滤。

### 5.18 数据导入、导出与备份

- 用户可导出自己的主机、分组、标签、终端偏好和命令片段。
- 默认导出不包含凭据；包含加密凭据的导出必须设置独立导出密码并再次认证。
- 导入前展示新增、覆盖、跳过和冲突数量，确认后再写入数据库。
- 管理员可创建 SQLite 一致性备份，并导出与数据库匹配的版本信息和校验值。
- 备份不得默认包含服务端主密钥；恢复加密凭据时必须提供原主密钥或执行明确的凭据失效流程。
- 恢复前验证格式、版本和完整性；恢复属于维护操作，需要阻止写入并形成审计记录。
- 提供备份保留数量和磁盘占用限制，失败时产生管理员可见告警。

### 5.19 空状态、错误与引导

- 首次登录时提供简洁的新增主机入口，不展示营销介绍页。
- 所有连接错误区分 DNS 失败、网络超时、端口拒绝、主机密钥异常、认证失败、tmux 缺失和 tmux 会话不存在。
- 错误提示面向用户给出下一步动作；详细堆栈和敏感连接信息仅进入受控服务日志。
- 长时间操作提供进行中、成功、失败和可重试状态，按钮防止重复提交。
- 删除、覆盖、终止、批量命令和公网端口监听等高风险动作使用一致的确认交互。
- 系统升级或维护时展示只读通知；已有远程 tmux 任务不应因前端维护页而结束。

## 6. 非功能需求

### 6.1 安全

- 生产环境必须使用 HTTPS/WSS。
- 密码使用 Argon2id 或 bcrypt 等可靠算法进行单向哈希。
- SSH 密码、私钥和口令使用服务端主密钥进行认证加密；主密钥不得存入 SQLite。
- 登录 Cookie 使用 `HttpOnly`、`Secure` 和合适的 `SameSite` 策略。
- 防护 CSRF、XSS、暴力登录、WebSocket 跨站劫持和越权访问。
- 日志对密码、私钥、令牌、Cookie 和终端敏感数据进行脱敏。
- 对主机地址进行访问策略控制，降低利用 Velin Web SSH 探测内网或云元数据地址的风险。
- 依赖库和 Go 模块需要定期安全扫描。
- 所有敏感写操作校验 `Origin`、登录状态和 CSRF 防护；WebSocket 握手必须验证允许的 Origin。
- WebSocket 连接使用短期授权或受保护 Cookie，不把长期令牌放在 URL 查询参数中。
- API 返回统一错误结构和请求 ID，不向客户端暴露 Go 堆栈、SQL、文件路径或密钥材料。
- 设置 Content Security Policy、`X-Content-Type-Options`、`Referrer-Policy` 等必要安全响应头。
- 凭据解密只发生在建立连接所需的最短生命周期内，避免在多个组件和日志上下文中复制明文。
- 对导入文件、上传文件名、主机别名、终端标题和审计字段统一进行长度限制和输出转义。

### 6.2 性能

- 常规网络环境下，键盘输入到终端回显应保持低延迟。
- 大量连续输出时进行批量传输和前端渲染节流，页面不得明显卡死。
- 输出缓冲、历史回放和 WebSocket 消息均设置明确上限。
- 首期目标容量需在开发前确认；建议基线为单实例 50 个在线用户、200 个活动 SSH 会话，并通过压测校准。
- 终端流应采用二进制 WebSocket 帧或等效低开销格式；控制消息使用有版本的结构化协议。
- 客户端对不可见终端降低渲染频率，但不得停止服务端读取远程输出。
- 工作区保存采用防抖及版本控制，避免拖动分屏时高频写入 SQLite。

### 6.3 可靠性

- 客户端 WebSocket 断开后自动指数退避重连。
- 后端需要避免单个 SSH 会话异常导致服务进程退出。
- SQLite 开启 WAL 模式、忙等待和定期备份。
- 数据库迁移必须版本化并支持部署时自动执行或显式执行。
- 服务异常后不得把内存中已失效的 SSH 会话错误标记为可继续连接。
- Go 服务启动后进行数据库迁移、主密钥可用性和配置合法性检查；关键检查失败时拒绝带病启动。
- SSH 重连采用有上限的指数退避，不因单台主机故障形成无限重试风暴。
- 对 tmux 状态探测设置超时和并发上限，远程命令挂起不得阻塞全局会话管理。
- 备份恢复流程至少需要一次自动化恢复演练测试。

### 6.4 可观测性

- 服务日志使用结构化格式，至少包含时间、级别、请求 ID、用户 ID、会话 ID 和事件类型；敏感字段必须脱敏。
- 提供健康检查和就绪检查，分别表示进程存活与数据库/关键配置可用。
- 提供活动 HTTP 请求、WebSocket、SSH 附着通道、tmux 恢复结果、连接延迟和错误计数等指标。
- 日志和指标不得包含密码、私钥、终端输入输出正文或完整 Cookie。
- 管理员界面展示近期系统错误摘要，但不能替代服务端日志和监控。

### 6.5 兼容性与可访问性

- 支持当前主流版本的 Chrome、Edge、Firefox 和 Safari。
- 桌面端最低建议宽度 1024px；移动端最低适配宽度 320px。
- 核心操作支持键盘访问，并提供可见焦点状态。
- 状态不能只依靠颜色区分。

### 6.6 国际化与时间

- 首期界面至少支持简体中文，代码和数据结构预留国际化键值。
- 时间在数据库中统一保存为 UTC，界面按用户时区展示。
- 文件大小、持续时间和日期格式在同一语言环境中保持一致。

## 7. 技术架构约束

### 7.1 前端

- Vue 3、TypeScript、Vite。
- Element Plus 作为基础 UI 组件库，并通过主题变量构建接近 Termius 的视觉风格。
- xterm.js 负责终端渲染，按需使用 fit、search、web-links 等官方插件。
- 状态管理建议使用 Pinia，路由使用 Vue Router。
- HTTP API 负责账户、主机、设置和工作区数据；WebSocket 负责终端数据及实时状态。
- P1 SFTP 界面采用虚拟列表和分块传输进度，避免大目录和大文件阻塞页面。
- 前端建立统一的命令面板，桌面端可用键盘搜索主机、会话和常用动作，移动端提供等价入口。

### 7.2 后端

- Go 单体服务同时提供 HTTP API、WebSocket 网关和 SSH 会话管理。
- 使用成熟的 Go SSH 库建立 SSH、请求 PTY、处理窗口尺寸变化和主机密钥校验。
- 通过远程 Velin Web SSH 专属 tmux socket 创建或附着持久终端；Go 内存会话负责当前 SSH 通道和客户端订阅，不作为任务存活的唯一载体。
- 后端启动时根据 SQLite 中的活动会话元数据进行状态核验；按需重新 SSH 连接并检查对应 tmux session，不盲目自动连接所有主机。
- 会话输出通过有界环形缓冲和单独写循环分发，慢客户端不得阻塞 SSH 读取。
- 服务端必须限制 WebSocket 消息大小、输入频率、会话数量和缓冲内存。
- tmux 管理封装为独立领域模块，只暴露创建、探测、附着、捕获、resize 和精确终止能力，业务层不得散落拼接 tmux 命令。
- SSH、SFTP 与端口转发可以复用受控连接，但各通道必须独立取消，关闭一个功能不能误断其他功能。

### 7.3 SQLite

- SQLite 保存用户、主机、加密凭据、工作区、会话元数据、设置和审计事件。
- SQLite 不保存活跃网络连接对象，只保存重新 SSH 连接和附着远程 tmux session 所需的安全映射与状态。
- 初始数据表建议包括：
  - `users`
  - `auth_sessions`
  - `host_groups`
  - `hosts`
  - `credentials`
  - `workspaces`
  - `terminal_sessions`
  - `session_clients`
  - `snippets`
  - `port_forwards`
  - `transfer_jobs`
  - `notifications`
  - `user_preferences`
  - `known_host_keys`
  - `audit_events`
- 数据表必须包含创建时间、更新时间；用户资源必须包含 `user_id` 并建立必要索引。
- `terminal_sessions` 至少保存主机、凭据引用、远程账号、tmux socket/session、所有者标记、状态、恢复结果和版本号，不保存 SSH 明文凭据。
- 工作区布局采用版本化 JSON 字段时必须进行服务端 schema 校验，并预留结构迁移能力。

## 8. 核心状态流转

### 8.1 新建终端

1. 用户选择主机并发起连接。
2. 后端校验用户对主机和凭据的访问权。
3. 后端校验主机指纹并建立 SSH 连接，检查远程 `tmux` 可用性。
4. 后端生成 Velin Web SSH 会话 UUID，在专属 socket 下创建同名 tmux session，并附着其 PTY。
5. 后端创建内存会话对象，并将 tmux 映射及状态写入 SQLite。
6. 浏览器通过 WebSocket 订阅终端会话并开始收发数据。
7. 前端将新会话加入工作区并保存布局。

### 8.2 浏览器关闭与恢复

1. 浏览器断开 WebSocket。
2. 后端移除客户端订阅；可以保持 SSH 附着通道，也可以 detach，但不得结束远程 tmux session。
3. 已连接期间的输出写入有界环形缓冲，会话元数据持续更新。
4. 用户再次打开页面并完成身份认证。
5. 前端读取最近工作区并获取各终端会话状态。
6. 后端复用现有 SSH 通道或重新连接目标主机，检查并附着专属 tmux session。
7. 优先从内存游标续传；Go 服务曾离线时从 tmux history 获取有限历史画面。
8. 回放结束后转入实时输出，恢复输入和尺寸控制。

### 8.3 会话过期

1. 会话达到配置的清理条件或被用户明确终止。
2. 后端仅在 Velin Web SSH 专属 socket 下精确终止对应 tmux session，再关闭 SSH/PTY 并记录结束状态和原因。
3. 已连接客户端收到结束事件。
4. 工作区仍可保留已结束标签，供用户查看状态或重新连接。

### 8.4 主动关闭终端标签

1. 用户点击 Velin 工作区内终端标签的关闭按钮。
2. 前端显示确认框，说明关闭将终止远程 tmux session 和其中任务，并提供“取消”“移到后台”“终止并关闭”三个动作。
3. 选择“移到后台”时只从工作区移除标签并解除浏览器订阅，tmux session 保持运行。
4. 选择“终止并关闭”时，后端校验用户、主机、远程账号、专属 socket、session 名和所有权标记。
5. 校验成功后仅执行精确 `kill-session -t <session_name>`；成功后更新数据库状态并从工作区移除标签。
6. 后端向该会话的全部观察客户端广播结束事件，各页面同步更新标签和状态。
7. 远程终止失败时保留标签或会话记录，显示失败原因和重试入口，不得仅在前端隐藏造成状态误判。

### 8.5 Go 服务重启恢复

1. Go 服务完成配置、主密钥和 SQLite 迁移检查后启动。
2. 服务读取数据库中的可恢复会话元数据，但不立即无上限连接所有远程主机。
3. 用户打开工作区或后台恢复任务按受控并发触发连接。
4. 后端使用保存凭据或向用户请求临时凭据，以创建会话时的同一远程账号 SSH 登录。
5. 后端在专属 socket 中精确查找 session，并核对 Velin 所有权标记。
6. 核验成功后获取 tmux 当前历史/画面并建立唯一附着通道；核验失败则进入等待认证、远程不可达、会话不存在或所有权异常状态。
7. 前端恢复布局和控制租约，再转入实时终端流。

### 8.6 多设备控制权转移

1. 第一个打开会话的客户端获得有期限的输入控制租约。
2. 其他客户端订阅相同输出，但处于只读状态，resize 消息被服务端忽略。
3. 新客户端请求接管时，原控制端在线则弹出确认；确认后服务端原子切换租约。
4. 原控制端离线或心跳超时后，服务端释放租约，等待中的客户端可以接管。
5. 服务端向所有客户端广播控制权变化，并使用新控制端的可见终端尺寸调整 PTY。

### 8.7 主机或会话删除

1. 删除主机配置前查询关联的活动 tmux 会话。
2. 若存在活动会话，用户只能取消、保留会话后删除配置，或明确终止会话后删除。
3. 选择保留时，数据库保留恢复所需的主机快照和凭据引用；在会话结束前不得清理依赖数据。
4. 终止操作校验用户、远程账号、专属 socket、session 名和所有权标记后，只删除精确目标。
5. 删除结果和失败原因写入审计，部分失败不得显示为全部成功。

## 9. API 与实时协议范围

具体接口在技术设计阶段确定，至少覆盖：

- 认证：登录、退出、刷新登录状态、当前用户、修改密码。
- 用户管理：列表、新建、禁用、重置密码、删除。
- 主机与分组：增删改查、搜索、连接测试。
- 凭据：增删改查、引用关系和临时凭据连接。
- 工作区：读取、保存、版本冲突处理。
- 终端会话：创建、列表、状态、重连、移到后台、关闭标签并终止、批量终止。
- 会话控制：申请控制权、释放控制权、查询观察者及控制端。
- 偏好设置：读取、保存、恢复默认。
- 命令片段：增删改查、变量解析和发送确认。
- SFTP：目录列表、上传、下载、移动、重命名、删除及传输任务状态。
- 端口转发：增删改查、启动、停止和运行状态。
- 通知：规则、权限状态、未读列表和已读操作。
- 导入导出与备份：预检、冲突确认、导出、备份、校验和恢复。
- 审计与系统状态：历史查询、健康检查和管理员指标。
- WebSocket 消息：协议协商、订阅、取消订阅、终端输入、终端输出、调整尺寸、控制租约、状态变化、心跳、输出确认和错误。
- HTTP 与 WebSocket 协议均带版本；服务端遇到不兼容客户端时返回明确升级提示。

### 9.1 终端会话状态

终端会话至少包含以下状态，数据库状态与实时连接状态需分开表达：

| 状态 | 含义 | 用户可执行动作 |
| --- | --- | --- |
| `creating` | 正在连接并创建 tmux session | 取消 |
| `attached` | Go 已附着，至少一个客户端正在查看 | 输入、只读观看、移到后台、关闭并终止 |
| `background` | tmux 运行中，当前没有浏览器查看 | 恢复、终止 |
| `reconnecting` | 正在重新 SSH 登录并检查 tmux | 等待、取消重试 |
| `auth_required` | 缺少或失效的 SSH 凭据 | 重新认证、终止记录 |
| `unreachable` | 远程主机暂时不可达 | 重试、保留、终止记录 |
| `ended` | tmux session 已不存在或正常退出 | 查看原因、新建会话、移除标签 |
| `ownership_error` | tmux 所有权标记不匹配 | 停止操作、联系管理员 |

- 网络失败不得立即把会话标记为 `ended`；只有确认 tmux session 不存在时才能结束。
- 状态变化包含稳定错误码、用户可读消息、发生时间和是否可重试。
- 客户端刷新后以服务端状态为准，本地缓存不得覆盖服务端终止或所有权异常状态。

### 9.2 页面信息架构

- `/login`：登录、锁定提示和首次改密。
- `/workspace`：终端标签、分屏、主机侧栏和后台会话，是登录后的默认页面。
- `/hosts`：主机、分组、标签、凭据引用、连接测试及批量操作。
- `/sessions`：当前附着、后台运行、等待认证、不可达和已结束会话。
- `/snippets`：P1 命令片段管理。
- `/transfers`：P1 SFTP 传输任务。
- `/forwards`：P1 端口转发管理。
- `/history`：个人连接历史和审计摘要。
- `/settings`：账户安全、终端外观、快捷键、通知及数据导出。
- `/admin`：用户、系统策略、会话监管、审计、健康状态和备份。
- 移动端保持相同信息架构，通过抽屉和底部操作区呈现，不另建功能不一致的移动版页面。

## 11. P0 验收标准

1. 未登录访问任何业务页面都会进入登录页，越权 API 返回明确错误。
2. 用户可创建密码或私钥认证的主机，并成功打开交互终端。
3. 同一页面至少可并行打开 4 个会话，并以标签或 2x2 分屏使用。
4. 调整窗口和分屏大小时，全屏终端程序的行列显示正确。
5. 执行一个持续输出任务后刷新页面，能够附着原 tmux session 并继续收发输入输出。
6. 执行长任务后关闭浏览器，等待一段时间重新登录，任务未被浏览器关闭中断，并能重新附着原 tmux session。
7. 离线期间输出未超过缓冲上限时，恢复后可以连续回放；超过上限时明确提示历史被截断。
8. 恢复工作区后，标签顺序、分屏结构、比例和活动会话与离开前一致。
9. 一个会话恢复失败不会阻止其他会话正常恢复。
10. 用户无法读取、订阅或终止其他用户的终端会话。
11. SQLite 中不存在明文登录密码、SSH 密码、私钥或私钥口令。
12. 手机竖屏和横屏均可登录、选择主机、使用终端、切换会话及调用常用控制键。
13. 使用已保存凭据时，Go 服务重启后能够根据 SQLite 映射重新 SSH 登录并附着仍存活的 Velin Web SSH tmux session，任务 PID 和运行状态保持连续。
14. 在远程默认 tmux socket 及另一个自定义 socket 中预建会话后，Velin Web SSH 的创建、枚举、恢复、终止和清理操作均不改变这些会话。
15. Velin Web SSH 终止一个会话时，只删除专属 socket 下指定的 `ws_<session_uuid>`，同一专属 socket 下其他 Velin Web SSH 会话仍正常运行。
16. 远程主机缺少 tmux 时，界面不得声称会话可记忆，并给出可操作的错误提示。
17. 使用临时凭据创建会话并重启 Go 服务后，远程 tmux 任务继续运行；用户重新输入同一账号凭据后可以附着，凭据未输入前界面明确显示“等待认证”，而不是“会话已丢失”。
18. 同一会话在两个浏览器中打开时，仅控制端可以输入和改变 PTY 尺寸；接管后原控制端立即变为只读。
19. 多行粘贴触发确认，取消后不会向远程终端发送任何字节。
20. 删除存在后台会话的主机时，界面明确展示关联会话并要求选择保留或终止，不会静默结束任务。
21. 移到后台、退出账号和管理员重启 Go 服务均不会触发远程 tmux `kill-session`。
22. 创建备份后可在测试环境恢复用户、主机、工作区和会话映射；缺少原主密钥时加密凭据明确标记为不可用。
23. 高速持续输出不会阻塞其他终端输入，慢速或后台浏览器不会阻塞后端读取 SSH 输出。
24. 所有 P0 连接错误至少能区分网络、指纹、认证、tmux 依赖和远程会话不存在，并提供对应处理入口。
25. 用户主动关闭一个运行中的 Velin 终端标签时必须先确认；确认后对应 tmux session 被精确终止，其中任务停止，其他 Velin 会话和非 Velin tmux 会话不受影响。
26. 用户在关闭确认框选择“移到后台”后，终端标签从工作区消失但 tmux session 和任务继续运行，可从后台会话列表恢复。
27. 关闭浏览器标签页、刷新页面或浏览器崩溃不会走“关闭终端标签”接口，也不会执行 `kill-session`。
28. 关闭终端标签时若远程终止失败，界面保留可见记录并显示失败状态，不得把仍运行的远程任务标记为已结束。
29. 移动端关闭终端标签采用相同确认流程，滑动或切换标签不会触发终止。
30. 同一会话在多个浏览器中打开时，一个控制端确认关闭终端标签后只执行一次幂等终止，其他浏览器立即收到结束状态；重复请求不会误伤其他 session。

## 12. 开发前待确认事项

以下项目不阻塞需求完善稿，但应在架构设计前确认：

- 部署模式是单用户私用、小团队使用，还是公网多租户。
- 预计同时在线用户数、每用户最大会话数和典型持续时长。
- 自动清理是否允许启用；当前默认永久保留，直到用户主动关闭终端标签、明确终止，或管理员明确终止。
- 目标主机需要支持的最低 tmux 版本，以及是否允许提供明确标记为不可恢复的临时直连模式。
- 是否需要保存终端输出到磁盘，以及留存周期和合规要求。
- 是否需要 SFTP、端口转发、跳板机和团队共享主机进入首期。
- 服务端主密钥的提供方式，例如环境变量、密钥文件或外部密钥服务。
- 首期是否只部署单个 Go 实例；SQLite 方案默认更适合单实例。

## 13. 首期明确不做

- P0 不包含多人同时输入同一终端，仅提供单写多读和控制权转移。
- P0 不包含 SFTP、端口转发、跳板机、SSH Agent、命令片段和浏览器通知，这些进入 P1。
- P0 不包含团队共享主机、细粒度资源授权、SSO 和多实例高可用。
- P0 不保存完整终端输入输出录像，只保存恢复所需的有限内存缓冲和远程 tmux history 映射。
- P0 不保证远程主机重启后 Shell 任务继续，也不自动安装 tmux 或修改目标主机的软件源。
- P0 不提供浏览器直连 SSH；所有 SSH 流量必须经过受控 Go 后端。

## 14. 明确不等价的能力

- “页面刷新后继续会话”不等于把终端文本重新画出来，而是重新附着同一个远程 tmux session 并恢复实时输入输出。
- “会话恢复”不是恢复原 SSH TCP 连接，而是重新建立 SSH 后附着同一个远程 Velin Web SSH tmux session。
- “工作区恢复”由 SQLite 提供；“任务连续运行”由远程 tmux 提供，两者组合后才能完整恢复现场。
- SQLite 负责持久化业务数据和 tmux 映射，不能序列化正在运行的 SSH TCP 连接。
- Velin Web SSH 专属 tmux socket 与用户默认 tmux 环境严格隔离；只给 session 名增加前缀不足以形成可靠隔离。
